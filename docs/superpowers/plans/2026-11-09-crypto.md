# Crypto Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track crypto coins held on an exchange (CoinDCX) as a third investment kind: 8-decimal quantities, entered amounts, FIFO, hand-entered prices, in the portfolio, dashboard and net worth, on the backend, website and Android app. Also list investment trades on an account's page, add the missing NAV-handover test, and fix the archive lock order.

**Architecture:** `instruments.kind` gains `"crypto"`. `investment_trades.quantity` widens from `Numeric(18,3)` to `Numeric(24,8)` with no change to any stock or fund output, which is pinned by golden fixtures. Crypto has its own routes (`/investments/coins`, `/investments/coin-prices`, `/investments/crypto-trades`) modelled on the fund routes. Trades move a `broker` account's cash through the existing balance engine, and the portfolio gains a `crypto` object. A new read-only `GET /accounts/{id}/investment-activity` feeds the account views.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, pytest (SQLite by default, PostgreSQL with `TEST_DATABASE_URL`). Next.js 16 (read `frontend/node_modules/next/dist/docs/` before writing pages). Expo SDK 58, Expo Router, react-native-paper (read the versioned Expo docs first, as `mobile/AGENTS.md` says). Client helpers are tested with `node --test` `.mjs` files.

**Spec:** [docs/superpowers/specs/2026-11-09-crypto-design.md](../specs/2026-11-09-crypto-design.md). Its "Design calls made by Claude" list is accepted and binding.

## Global Constraints

- Money crosses the API as strings with 2 decimals (`fmt`). Crypto quantity is a string with **8** decimals (`"0.00014067"`), and crypto price has **4** (`"7504827.5000"`). Dates are ISO `YYYY-MM-DD`.
- **No existing stock or fund response may change.** Stock quantity stays an int, and fund units stay 3 decimals. `tests/fixtures/stock_figures.json` and the new `fund_figures.json` are never edited after Task 1.
- All arithmetic is `Decimal`, rounded `ROUND_HALF_UP` to paise, never floats or SQL `SUM`.
- Validation errors: `RequestValidationError([field_error(field, message)])` → 422. Conflicts → 409. Missing or other-user or other-kind ids → 404. Every query is scoped to `user.id`.
- Account choice for crypto: an active `broker` account only.
- The installed Android app must keep working: existing endpoints keep their shapes, and new data goes only in new keys or new endpoints.
- Clients only display server figures. They do no money arithmetic, except the inline mismatch warning, which mirrors the server rule with exact BigInt maths.
- Web and Android each get their own UI. Never port one into the other.
- Subagents never start servers, emulators or browsers in the foreground. Long-running processes run in the background with a bounded readiness check (poll `http://localhost:8000/api/health` at most 30 times, 1 second apart), and are stopped at the end of the task.
- Browser checks use a throwaway test user on the local API, never the owner's data. **Never run `npm run build` in `frontend/`**: the owner's `next start` uses `frontend/.next`, and a `next dev` may also be running there. Use `npx tsc --noEmit`, `npm run lint` and `npm test`.
- Commit after each task, ending messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A fund or stock input with more decimals than its kind allows, now that the column holds 8.** `units "1.2345"` on a fund trade and `quantity 1.5` on a stock trade must still be 422 (Task 2 tests).
2. **A coin with only an opening lot and no price.** It shows at cost, with value = invested and unrealised 0.00, and average price = `fmt_price(amount ÷ qty)` (Task 5 test).
3. **Selling part of a coin with 8-decimal lots.** Selling 0.00005 of 0.00014067 BTC costing 994.11 takes `round_paise(994.11 × 0.00005 ÷ 0.00014067) = 353.35`, and leaves 0.00009067 costing 640.76 (Task 4 test).
4. **Archiving CoinDCX while it holds coins**, or while it holds shares. Each is refused with its own message (Task 5 test).
5. **An account's activity for a month with a SIP, a stock buy, a crypto sell and an opening lot.** The opening lot is left out, signs are right, and the SIP is labelled (Task 6 test).
