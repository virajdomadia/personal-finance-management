# First-run Setup and Empty States Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A guided setup checklist for new users on the website and Android dashboards (salary account, cards, loans, salary/rent/SIPs, investments, and Bank SMS on the app), with progress, skip and resume; plus a written empty state on every list screen of both clients.

**Architecture:**
- **Backend:** `GET /api/setup` in `backend/app/api/routes/setup.py`, five steps whose `done` and `count` come from the user's data. No tables, no migration.
- **Clients:** a pure helper `lib/setup.ts` on each client (step list, progress, mode rules, stored-state parsing) with `node --test` tests, and one self-contained `SetupChecklist` component per client, inserted on the dashboard with one line.
- **Device state:** `{mode: "open" | "later" | "hidden", none: string[]}` under the key `gullak.setup` (web `localStorage`, app `expo-secure-store`).
- **Empty states:** one `EmptyState` component per client, used by every list screen except the investment screens, where only the text changes.

**Spec:** [docs/superpowers/specs/2026-11-12-first-run-design.md](../specs/2026-11-12-first-run-design.md). Its "Design calls made by Claude" list is binding.

## Global Constraints

- No money crosses `/api/setup`. Clients do no money arithmetic.
- No existing response shape changes. No migration.
- Web and Android each get their own UI.
- No new native modules on the app (`expo-secure-store` is already installed).
- The dashboard change on each client is one component plus a one-line insertion (parallel work touches both dashboards).
- On investment screens, only empty-state text changes (parallel "Add investment" work).
- New `*.test.mjs` files are added to the client's `test` script.
- Commit after each task, ending messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
