# Goals and Baskets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Goals with baskets of earmarked bank, cash and wallet money and whole holdings, an emergency fund whose target is worked out from recorded expenses, a free balance on accounts, and a monthly set-aside reminder. Plus four folded follow-ups. All of it on the backend, website and Android app.

**Architecture:**
- **Tables:** three new ones, `goals`, `goal_earmarks` (append-only signed entries) and `goal_holdings` (an instrument or a PPF/RD account, with an `active` flag mirroring its goal so a partial unique index keeps each holding in one active goal).
- **Maths:** pure functions in `backend/app/api/goals.py`.
- **Routes:** `routes/goals.py` (prefix `/goals`).
- **Accounts:** gain `set_aside`, `free_balance` and `in_goal`, and archiving gains goal and policy checks under one id-ordered lock.
- **Reminders:** goal reminders go under new keys (`goals_due`) in `/recurring/due` and the dashboard, never inside `items`.

**Tech Stack:**
- **Backend:** FastAPI, SQLAlchemy 2, Alembic, pytest (SQLite by default, PostgreSQL with `TEST_DATABASE_URL`).
- **Website:** Next.js 16 (read `frontend/node_modules/next/dist/docs/` before writing pages).
- **Android:** Expo SDK 58, Expo Router and react-native-paper (read `mobile/AGENTS.md` first).
- **Client helper tests:** `node --test` `.mjs` files.

**Spec:** [docs/superpowers/specs/2026-11-11-goals-design.md](../specs/2026-11-11-goals-design.md). Its "Design calls made by Claude" list is accepted and binding.

## Global Constraints

- Money crosses the API as 2-decimal strings, and dates as ISO `YYYY-MM-DD`. Use `Decimal` only, `ROUND_HALF_UP`, and no floats. Sums are done in Python, not SQL `SUM`.
- "Today" is `today_india()`. Day clamping uses `clamped_date` from `app/api/dates.py`.
- Validation errors are `RequestValidationError([field_error(field, message)])` → 422. Conflicts are 409. Missing, other-user or wrong-kind ids are 404. Every query is scoped to `user.id`.
- **Goals never move money.** No goal route creates, edits or deletes a transaction. Net worth, `total_have` and `total_owe` are unchanged by anything in this plan.
- No existing response shape may change except by adding keys. The installed Android app reads `item.template` on every `/recurring/due` and dashboard `recurring` item, so goal reminders must never appear there.
- The golden tests `tests/test_pg_stock_figures.py` and `tests/test_pg_fund_figures.py` must keep passing, and their fixtures are never edited.
- Web and Android each get their own UI. Clients only display server figures. They do no money arithmetic.
- Subagents never start servers, emulators or browsers, and never run anything in the foreground that doesn't exit. **Never run `npm run build` in `frontend/`.** Verify with `npx tsc --noEmit`, `npm run lint` and `npm test`. The controller does the website browser walk.
- A full PG run takes over an hour. Per task, run on PG only the changed test files plus the two goldens: `TEST_DATABASE_URL=postgresql+psycopg://pfm:pfm@localhost:5434/pfm_test` (start the cluster with `npm run db:start` from the root if it's down).
- Run `ruff format` only on files you touch.
- Commit after each task, ending messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Spending the earmarked money.** A bank with ₹80,000 earmarks ₹50,000 for EF and ₹40,000 for Bike. Its `free_balance` is −10,000.00, and both the account and both goals carry the warning "₹10,000 more is set aside than HDFC holds." Nothing is released (Task 5 test).
2. **Two requests putting the same fund into two goals at once.** The partial unique index turns the loser into a 409, not a duplicate (Task 1 index, Task 4 PG test).
3. **Archiving the bank while money is being set aside in it.** Both lock the account row first, so either the set-aside sees an archived account (422) or the archive sees the earmark (409), never both succeeding (Task 4 and Task 5 tests).
4. **A goal restored after its fund joined another goal.** The restore is refused with "{fund} is in {goal} now." and nothing changes (Task 4 test).
5. **The emergency fund with only the current month recorded, or a first month starting on the 20th.** No target and the "Not enough history" state in the first case. In the second, that month is left out of the average (Task 2 and Task 3 tests).

**Files:**

**Interfaces (produces):**
```python
Month = tuple[int, int]  # (year, month)

class ExpenseFigure(NamedTuple):
    amount: Decimal | None   # None: no fully recorded month yet
    months: list[Month]      # the months averaged, oldest first

def expense_window(first_tx: date | None, today: date) -> list[Month]
    # the last 6 calendar months before today's month, dropping months before first_tx's month,
    # and first_tx's month itself unless first_tx.day == 1
def monthly_expenses(spend: dict[Month, Decimal], first_tx: date | None, today: date) -> ExpenseFigure
    # average over expense_window (missing months count as 0), round_paise half up
def months_left(target_date: date, today: date) -> int  # this month through the target's month, inclusive; 0 if past

class Progress(NamedTuple):
    percent: int | None      # saved ÷ target × 100, half up to a whole number; None without a target
    reached: bool
    months_left: int | None  # None without a date
    per_month: Decimal | None  # (target − saved) ÷ months_left rounded UP to the rupee; None if reached, no date or no months left
    overdue: bool            # date passed and not reached

def progress(target: Decimal | None, saved: Decimal, target_date: date | None, today: date) -> Progress
def reminder_due(monthly_amount: Decimal | None, reminder_day: int | None, reminder_start: date | None,
                 set_aside_this_month: Decimal, reached: bool, today: date) -> Decimal | None
    # the amount still to set aside this month, or None when nothing is due
```
- A reminder is due when `monthly_amount` is set, today's month ≥ `reminder_start`'s month, today ≥ `clamped_date(today.year, today.month, reminder_day)`, the goal isn't reached, and `set_aside_this_month` < `monthly_amount`. Only the current month is ever due.

**Interfaces (produces):**
- `load_goal_book(db, user_id, today) -> GoalBook`. It loads every goal, earmark and holding once. Task 4 (warnings), Task 5 (accounts) and Task 6 (reminders, dashboard) use it:
  - `set_aside_by_account: dict[int, Decimal]` covers active goals only;
  - `holding_goal: dict[("instrument"|"account", id), (goal_id, goal_name)]` covers active holdings only;
  - `responses: dict[int, GoalResponse]`.
- `GoalResponse`:
  ```
  {id, name, kind, target: str|null, target_date, note, archived,
   ef: {months, monthly: str|null, computed: str|null, override: str|null, window: ["2026-06", ...]}|null,
   monthly_amount, reminder_day,
   saved, earmarked, holdings_value, percent: int|null, reached, months_left: int|null, per_month: str|null, overdue,
   earmarks: [{account_id, account_name, amount}],
   holdings: [{id, kind: "stock"|"mutual_fund"|"crypto"|"ppf"|"rd", instrument_id|null, account_id|null,
               name, value, status: "held"|"sold"|"closed", note: str|null}],
   warnings: [str]}
  ```
  - `earmarks` lists only accounts with a non-zero sum.
  - A holding's `note` is "Also funds the {insurer} premium." when an active policy's `funded_by_id` is that account.
- Spending per month for the EF: `expense` amounts plus the full `amount` of `emi` transactions, by calendar month of `date`. `first_tx` is the user's earliest transaction date of any type. The EF target is `ef_months × (override or computed)`, or null when neither exists.
- Holding values:
  - instruments: the per-instrument `summarise(replay, prices, only={id}).value`;
  - PPF/RD accounts: `balance_of`.
  - `status` is "sold" when quantity is 0, "closed" when the account is archived, otherwise "held". Sold and closed holdings count as 0.
- Endpoints:
  - `GET /goals?archived=false` → `{"goals": [...]}`, the emergency fund first, then by name.
  - `GET /goals/{id}` → `GoalResponse` + `history: [{id, account_id, account_name, amount, date, note}]`, newest first.
  - `POST /goals` → 201.
  - `PATCH /goals/{id}`.
  - `DELETE /goals/{id}` → 409 "This goal has set-aside history. Archive it instead." if it has any earmark entry.
- Validation:
  - `name` is 1–60 characters: "Enter a name."
  - `kind` is custom or emergency.
  - custom: `target_amount` > 0, "Enter a target amount."
  - emergency: a `target_amount` is refused, "The emergency fund's target is worked out for you."; `ef_months` is 1–24, default 6, "Choose 1 to 24 months."; the override, if given, is > 0.
  - A second active emergency fund → 409 "You already have an emergency fund."
  - `monthly_amount` > 0 requires `reminder_day` 1–31, "Choose a day from 1 to 31."
  - Turning the reminder on (null → set) sets `reminder_start` to the 1st of today's month.

### Task 4: Baskets: set aside, release, holdings, archive and restore

**Files:**
- Modify: `backend/app/api/routes/goals.py`
- Test: `backend/tests/test_goals.py`, `backend/tests/test_pg_concurrency.py`

**Interfaces (produces):**
- `POST /goals/{id}/earmarks` `{account_id, action: "set_aside"|"release", amount, date?, note?}` → 201 `GoalResponse`.
  - Lock with `lock_accounts(db, user.id, [account_id])` first, then the goal row.
  - The account must be the owner's active `bank`, `cash` or `wallet`, else 422 on `account_id` "Set money aside from a bank, cash or wallet account."
  - `amount` > 0. A release is stored negative.
  - `date` defaults to today and can't be after it.
  - A release beyond the goal's earmark in that account → 422 on `amount` "Only ₹{x} of {account} is set aside for this goal." (Indian grouping, whole rupees drop `.00`).
  - On an archived goal → 409 "Restore this goal first."
  - A set-aside may exceed the free balance (it only warns).
- `DELETE /goals/{id}/earmarks/{entry_id}`: refused with 409 "Delete the later release first." if it would leave the goal's earmark in that account below zero.
- `POST /goals/{id}/holdings` `{instrument_id}` or `{account_id}` (an active PPF or RD) → 201.
  - Already in an active goal → 409 "{name} is already in {goal}." This is checked first, and an `IntegrityError` from the partial index maps to the same 409.
  - `DELETE /goals/{id}/holdings/{holding_id}`.
- `POST /goals/{id}/archive` sets `archived_at` and sets the goal's holdings `active` to false.
- `POST /goals/{id}/restore` reactivates them, refusing with 409 "{holding} is in {goal} now." (Review Focus 4) or "You already have an emergency fund." and changing nothing.
- `warnings` (in the Task 3 response): for each account in the goal's earmarks whose `free_balance` (Task 5's formula, from `GoalBook.set_aside_by_account`) is negative, "₹{−free} more is set aside than {account} holds."
