# Stocks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manual stock tracking: stocks, buy/sell/existing-shares trades through broker accounts, manual prices, FIFO holdings with realised and unrealised P&L, counted in net worth, on the backend, website and Android app.

**Architecture:** Three new tables (`stocks`, `stock_trades`, `stock_prices`). Holdings are never stored. A pure module (`app/api/portfolio.py`) derives them from trades with FIFO. Trade cash joins the existing balance engine as extra `Movement`s, so broker balances, "You have" and net worth stay right with no other change. New routes live under `/api/investments`. Each client gets its own Investments screens.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, pytest (SQLite by default, PostgreSQL with `TEST_DATABASE_URL`). Next.js 16 (read `frontend/node_modules/next/dist/docs/` before writing pages). Expo SDK 58 with Expo Router and react-native-paper (read the versioned Expo docs first, as `mobile/AGENTS.md` says). Pure client helpers are tested with `node --test` `.mjs` files.

**Spec:** [docs/superpowers/specs/2026-11-08-stocks-design.md](../specs/2026-11-08-stocks-design.md)

## Global Constraints

- Money goes over the API as strings with 2 decimals (`fmt` in `backend/app/api/routes/accounts.py`). Money inputs are parsed with the existing `Money` type (text only, at most 2 decimals, under `MAX_MONEY`).
- Validation errors use the existing format: `RequestValidationError([field_error(field, message)])` → 422 with `detail[].loc == ["body", field]`. Conflicts are `HTTPException(409, message)`. Missing or other-user ids are 404.
- Every query is scoped to `user.id`. Ids outside `1..MAX_ID` are 404, never a database error.
- "Today" is `today_india()`. Trade and price dates can't be in the future: `"The date can't be in the future."`
- Shares are whole numbers, 1 to 100000000 (10,00,00,000).
- Rounding is half up to paise (`ROUND_HALF_UP`, `Decimal("0.01")`), and all sums use `Decimal` in Python, never SQL `SUM`.
- Sort order: trades by `(date, buys before sells, id)` for FIFO. Lists are newest first: `date desc, id desc`.
- Web and Android get their own UI. Never port one into the other.
- P&L is always shown with a sign (`+₹1,234.50`, `−₹250.00`, `+12.34%`), with green for gain and red for loss, so colour is never the only signal.
- Commit after each task, ending messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A sell whose charges are more than the sale value.** Refuse it on `charges`: "Charges can't be more than the sale value." (test in Task 4).
2. **Editing an old buy so that a later sell is short** (lower quantity, later date, other broker or other stock). Refuse it with 409, and leave the stored trade unchanged (test in Task 4).
3. **Selling everything, then buying again.** The position reopens with only the new lot's cost, and the earlier realised P&L is kept (test in Task 2).
4. **A trade so large that quantity × price overflows the money column.** Return 422 "This trade is too large.", never a 500 (test in Task 4).
5. **Two prices recorded for the same date.** The later-recorded one is current (test in Task 3).

### Task 2: FIFO portfolio maths (pure)

**Files:**
- Create: `backend/app/api/portfolio.py`
- Test: `backend/tests/test_portfolio_math.py`

**Interfaces:**
- Produces:
  ```python
  class TradeRow(NamedTuple):
      id: int; stock_id: int; account_id: int; side: str; date: date
      quantity: int; price: Decimal; charges: Decimal; opening: bool

  def trade_cash(t: TradeRow) -> Decimal
      # signed broker cash: buy −(q×p+c), sell +(q×p−c), opening buy 0
  def trade_value(t: TradeRow) -> Decimal
      # unsigned: buy q×p+c, sell q×p−c (opening buys too)

  @dataclass
  class Position:
      stock_id: int; account_id: int
      shares: int = 0; invested: Decimal = 0; realised: Decimal = 0; sold_any: bool = False

  class Replay(NamedTuple):
      positions: dict[tuple[int, int], Position]   # key (stock_id, account_id)
      realised_by_sell: dict[int, Decimal]         # sell trade id → its realised P&L
      shortfall: TradeRow | None                   # first sell selling more than held, in order

  def replay(trades: Iterable[TradeRow]) -> Replay
  def round_paise(value: Decimal) -> Decimal
  ```
- Algorithm (the part the tests don't fully fix): per `(stock_id, account_id)`, walk the trades sorted by `(date, 0 if buy else 1, id)`, keeping a FIFO deque of lots `[shares, cost]`. A buy appends `[q, q×p+c]`. A sell takes from the front. A whole lot gives its whole cost. A partial take gives `round_paise(cost × taken / lot_shares)`, and the lot keeps the rest of the cost. Realised = `(q×p − c) − cost taken`. If a sell needs more shares than the deque holds, record the first such sell as `shortfall` (once) and take what's there.
