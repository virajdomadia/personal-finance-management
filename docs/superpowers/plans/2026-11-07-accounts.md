# Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a signed-in user add, view, edit, archive, and restore five types of account on web and Android, with server-computed "have" and "owe" totals.

**Architecture:** One `accounts` table and one FastAPI router own all rules and arithmetic. Money crosses the API as decimal strings. Each client has its own native UI plus a small tested library for formatting and form payloads.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, PostgreSQL (tests on SQLite), Next.js 16 with Tailwind, Expo 58 with Expo Router and react-native-paper.

**Spec:** `docs/superpowers/specs/2026-11-07-accounts-design.md`. Read it first. Its field table, balance sign rules, totals, display rules, and API table are requirements and are not repeated here.

## Global Constraints

- Work on branch `feature/accounts`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never store full card numbers, full account numbers, CVV, PINs, or banking passwords. `last4` is the most the app holds.
- Never parse money into a binary float: not in the database, the API, or client code. Clients format the server's strings and do no money arithmetic.
- Another user's account returns 404 on every route that takes an ID.
- Web and Android get separate, platform-native UIs. Don't share UI code or make one copy the other.
- Build order: backend, website, deploy, then app. The app only ever calls the deployed API, never a LAN IP or local backend.
- Production migration and deployment need the owner's explicit go-ahead at Task 5.
- Before writing Next.js code, read the relevant guide in `frontend/node_modules/next/dist/docs/`. Before using an Expo API, fetch `https://docs.expo.dev/versions/v58.0.0/`. Install mobile packages only with `npx expo install`. This plan needs no new packages.

## Review Focus

- Money typed the way people write it (`1,00,000`, `₹500`, ` 250.50 `) is accepted on both clients, not rejected.
- Nonsense money values (`NaN`, `Infinity`, `1.234`, JSON numbers, 13-digit rupee amounts) return a 422, never a 500 or a rounded value.
- A balance of `-0` or `-0.00` displays as `0.00`, not as negative zero.
- A double-click or double-tap on save creates only one account, because the button is disabled while saving.
- Editing an account that was archived on the other device (409) shows a clear message and refreshes the list, instead of failing silently.

- [ ] **Step 4: Implement the routes in `backend/app/api/routes/accounts.py`**

- Router: `APIRouter(prefix="/accounts", tags=["accounts"], dependencies=[Depends(get_current_user)])`, included in `api_router`.
- `AccountCreate` uses `ConfigDict(extra="forbid", str_strip_whitespace=True)`.
- `Money = Annotated[Decimal, BeforeValidator(<reject anything that isn't a str>), Field(max_digits=14, decimal_places=2)]`. This rejects JSON numbers, and the limits give the spec's magnitude cap.
- `last4` uses the pattern `^[0-9]{4}$`, not `\d`, which also matches non-ASCII digits.
- Blank `institution` becomes null.
- `validate_rules` holds everything per-type, from this table, and raises `RequestValidationError` with `loc: ("body", field)`. It rejects non-null values for fields not in the type's set, and a missing `name`, `balance`, or bank `bank_kind`. It applies the sign rules and `credit_limit > 0`.

```python
APPLICABLE = {
    "bank": {"institution", "bank_kind", "last4"},
    "credit_card": {"institution", "last4", "credit_limit", "statement_day", "due_day"},
    "cash": set(),
    "broker": {"institution"},
    "wallet": {"institution"},
}
```

- `to_response` formats money with `f"{value + 0:.2f}"`, where `+ 0` turns `-0` into `0`. It sets `available_credit = credit_limit - opening_balance`, or null with no limit.
- `GET` loads all the user's accounts once, computes totals over the active ones with Python `Decimal` `sum`, and returns the requested set sorted by `(TYPE_ORDER, name.casefold(), id)`. `?archived=true` returns only archived accounts, with totals still covering active ones.
